# Power Platform and Copilot Managed Runtime setup (workspace entry)

Read and follow [`skills/power-platform-setup/SKILL.md`](../../../skills/power-platform-setup/SKILL.md), [`AGENTS.md`](../../../AGENTS.md), and [`Setup.ps1`](../../../Setup.ps1) in this repository.

- Speak in plain, non-technical language. Never require the user to know CLI flags or plugin IDs.
- **Ask which product track first (unless already named):** **Power Platform** (Model-driven, Canvas, Code Apps, Power Automate, Dataverse, etc.), **Copilot Managed Runtime (Managed Apps)** (`copilot-managed-runtime` + `@microsoft/cmr-cli` `ms`), or **Both**.
- **Allow selecting multiple Power Platform workloads at once:** never list individual plugins as single-select `ask_user` `choices` (which forces picking only one!). Use `multiSelect: true` only where supported; in single-select `ask_user` hosts (like GitHub Copilot), show the numbered 1–11 Power Platform workload list and use freeform input (no `choices`) or multi-plugin bundle presets so the user can pick several (e.g. `1, 2, 6` or `Model-driven apps, Power Automate`), and append `copilot-managed-runtime` when **Both** is selected so `Setup.cmd -Plugins "id1,id2,..." -Prerequisites FromPlugins` resolves the combined union of prerequisites (including Node >= 24.11.0, Git + GCM, and `@microsoft/cmr-cli` whenever CMR is included).
- **For `CopilotApp` (GitHub Copilot desktop app), wait for confirmation at each in-app step before moving to environment connection:** add each needed marketplace one at a time with `-PluginHost CopilotApp -MarketplaceOnly -Marketplace <PowerPlatform|CopilotManagedRuntime> -Prerequisites FromPlugins -AcceptPlugins` and wait (`ask_user`) for confirmation; then trigger each selected plugin one at a time with `-PluginHost CopilotApp -Plugins "<single-id>" -SkipMarketplace -Prerequisites FromPlugins -AcceptPlugins` and wait (`ask_user`) for plugin installation confirmation **before** asking about environment connection!
- **For CMR-only setups**, finish by pointing to `ms auth login` / `/copilot-managed-runtime:create-app` (do not push PAC/Azure connection setup unless they also want Dataverse data sources). **For Power Platform / Both environment connections, always follow `skills/power-platform-connect/SKILL.md` (never bare `pac auth create`):** check which prerequisites (`pac`, `az`, `node`) and whether the `dataverse` plugin are installed; show any device code **in bold** (`**CODE**`) with `[Sign in to your account](https://login.microsoftonline.com/common/oauth2/deviceauth)` inside the question; save the approved token-free `connections\<alias>.json` record; offer `.\Setup.cmd -NonInteractive -ConnectionSkillHost <host> -AcceptConnectionSkill` (separate approval); and remind GitHub Copilot desktop users to **End task** in Task Manager if needed on restart and ensure skills are toggled **on** in **Customize > Installed**.
- If the user already named one or more workloads (for example *"set up Copilot Managed Runtime"* -> `copilot-managed-runtime`, or *"install the prereqs for model-driven apps and power automate"* -> `model-apps,power-automate`), run `.\Setup.cmd -CheckOnly -Plugins "<ids>" -Prerequisites FromPlugins` immediately, explain what is ready vs missing, and obtain explicit approval before installing anything.
